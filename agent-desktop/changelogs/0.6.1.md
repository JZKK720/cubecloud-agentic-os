# Changelog — v0.6.0 → v0.6.1

## V0.6.0 was shipped with a broken asar

The v0.6.0 release at
https://github.com/JZKK720/cubecloud-agentic-os/releases/tag/v0.6.0
bundled the wrong tree into `app.asar`. When `electron-builder` ran
from the monorepo root, it walked up the directory tree looking for
`package.json`, found the outer monorepo root's `package.json`
instead of the inner app's, and bundled the outer tree by mistake.

Symptoms (visible to a v0.6.0 user on launch):

- **Blank window.** The renderer's `index.html` was actually a
  stray `highlight.js` LICENSE file because that was the first HTML
  the wrong-tree walk happened to find.
- **Wrong main-process entry.** The Electron main script pointed at
  boilerplate license text instead of the real `index.ts`.
- **24,794 entries** in the asar (the entire monorepo), not the
  ~hundreds of files the real inner app ships with.
- **i18n, Headroom, CodeGraph, and Provider surfaces all missing** —
  none of the inner main-process modules were bundled.

The auto-updater also pointed new v0.6.0 installs at the broken asar
on subsequent runs, so the only fix was a fresh installer.

## V0.6.1 fixes it

`V2.10.43a` (commit `3490df0`) closed the bundle-source bug at the
config level. `V2.10.43b` (commit `7d21aa6`) aligned the npm package
name, the executable name, and the updater cache to
`cubecloud-agent-desktop` so the auto-updater could find v0.6.1
on the existing v0.6.0 install path. `V2.10.43d` (commit `a7e117d`)
bumped `agent-desktop/package.json` from `0.6.0` to `0.6.1` and
shipped the new build.

V0.6.1 was published at
https://github.com/JZKK720/cubecloud-agentic-os/releases/tag/v0.6.1
with 4 assets (`cubecloud-agent-desktop-0.6.1-setup.exe`,
`cubecloud-agent-desktop-0.6.1-portable.exe`, the blockmap, and
`latest.yml`), all SHA-256 verified, all download URLs HTTP 200.
v0.6.0 was marked as pre-release (superseded).

## Upgrade path for v0.6.0 users

The `electron-updater` client on a v0.6.0 install reads
`latest.yml` from the v0.6.1 release, sees a new version, and offers
the upgrade in-app. The user clicks upgrade; the auto-updater
downloads `cubecloud-agent-desktop-0.6.1-setup.exe` (415 MB),
verifies the SHA-256 against `latest.yml`, and runs it
side-by-side. No manual uninstall required.

A user who installed v0.6.0 and now sees only the blank-window
state: open Settings → Updates → Check for updates → upgrade. The
same `cubecloud-agent-desktop-updater` cache that was set in
V2.10.43b carries the v0.6.1 binary across the upgrade.

## What did NOT change between v0.6.0 and v0.6.1

- No source code change (the bug was in the **build configuration**,
  not the application).
- No `package.json` workspace change.
- No `scripts/sync-docs.ps1` change.
- No new tests (the V2.10.43a regression test is the test; the bug
  couldn't have been caught by a runtime test).
- No translation / i18n change.
- No `BRANDING_AND_LICENSE.md` transition (the v0.6.0 → v0.6.1
  transition is recorded in `V2.10.36-HANDOFF.md` §V2.10.43a–d
  because it was a build fix, not a user-visible product change).

## Out of scope for v0.6.1 (deliberate)

- **macOS / Linux installers.** v0.6.1 was built Windows-only. The
  release workflow has 6 jobs; only `release_windows` and `publish`
  are Windows-runnable. Mac and Linux users on the v0.6.0 install
  path cannot get the fix yet. The release.yml workflow is in
  place; triggering the other 4 jobs requires a Mac CI runner or
  local macOS / Linux build infra.
- **v0.6.2 (post-rename build).** The V2.10.43c directory rename
  (`cubecloud-desktop/` → `agent-desktop/`) is on main but no
  v0.6.2 build has been published. The v0.6.1 binary was built
  from the pre-rename path; the rename is purely a source-tree
  change. The next published build will be v0.6.2 from the new
  path.
- **Native-speaker review of the inner CJK translations.** Same
  priority as before; needs Japanese / Chinese reviewers.
