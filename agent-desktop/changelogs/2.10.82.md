# cubecloud-agent-desktop v2.10.82 — release notes

**Source:** `origin/main` of
[JZKK720/cubecloud-agentic-os](https://github.com/JZKK720/cubecloud-agentic-os)
**Supersedes:** v2.10.81 (tag on `origin/main`)
**Internal version:** still `2.10.81` in `agent-desktop/package.json` —
this file is the pending release notes; the `chore(release)` version
bump lands when the release is cut.

## What this release changes

V2.10.81 → this change is an **i18n completeness fix**. 165 literal
`t("namespace.key")` calls had no entry in any locale dictionary, so the
affected screens rendered the raw key on screen (for example
`codegraph.title` instead of `CodeGraph`). This shipped visibly in the
README preview gallery.

### Root cause

The `codegraph`, `toolSuggestions`, and `worktree` namespaces existed only
as `t()` call sites — no locale file was ever created, and none of the
three was registered in `agent-desktop/src/shared/i18n/index.ts`. Seven
more namespaces (`headroom`, `everos`, `tools`, `common`, `welcome`,
`settings`, `sandboxTasks`) had file coverage but were missing the newer
key groups those screens use.

The existing CI gate (`scripts/check-i18n-coverage.cjs`) could not catch
this. Its key regex only matched **quoted** keys, so it parsed 57 keys out
of ~1,470 and compared locales only against each other — never against the
keys the renderer actually calls. It reported `✅ no drift` while six
screens rendered as raw keys.

### What changed

- **New namespaces:** `codegraph.ts`, `toolSuggestions.ts`, and
  `worktree.ts` in `en` (natively written) and `zh-CN` (natively written).
  The other six locales re-export the English file, matching the existing
  `headroom` convention.
- **Extended namespaces:** added the missing key groups to `headroom`,
  `everos`, `tools`, `common`, `welcome`, `settings`, and `sandboxTasks`
  in `en` and `zh-CN`.
- **Registered all three new namespaces** under every one of the eight
  locale `resources` blocks in `src/shared/i18n/index.ts`.
- **`codegraph.repos`** changed from a string to `{ title, empty }` so a
  leaf key can be a namespace prefix; `CodeGraph.tsx` now reads
  `t("codegraph.repos.title")`.
- **Repaired `scripts/check-i18n-coverage.cjs`** to parse bare *and*
  quoted keys and prefix them with the namespace filename. It now sees
  1,573 keys instead of 57.
- **Added `tests/i18n-renderer-keys.test.ts`** — two test cases that fail
  on the previous state: every literal renderer key must resolve to real
  copy in `en`, and must fall back to real copy (not a raw key) in the
  other seven locales.
- **Recaptured `previews/codegraph.png` and `previews/everos.png`**, which
  were the two README images that showed raw keys.
- **Untracked the two committed `__pycache__/*.pyc` files** and ignored
  Python bytecode going forward.

### Verification

- `npm run typecheck` (agent-desktop): clean.
- `npx vitest run tests/i18n-renderer-keys.test.ts`: 2 passed.
- `node scripts/check-i18n-coverage.cjs --strict`: exits 1 with the
  now-accurate drift table (the six English-fallback locales report
  missing native copy; `zh-CN` is 54 keys short). This is the intended
  behaviour once the gate can see the real key tree — the previous
  `✅ no drift` was a false negative.

### Known remaining gaps

- `zh-CN` is missing 54 keys, and the six English-fallback locales are
  missing ~326–344 keys each, all of which currently fall back to English
  copy. Native translation is a follow-up.
- `previews/tools.png` still predates this change; the capture pipeline
  fails on the Tools tab (click timeout) and needs a separate fix.
- Pre-existing failures unrelated to this work: `packages/platform-core`
  typecheck (`@types/node` not declared) and 14 renderer tests that fail
  on `localStorage` being undefined in the jsdom environment.
