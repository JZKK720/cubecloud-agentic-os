## What this release changes

V2.10.81 → this change is an **i18n completeness fix**. 165 literal
`t("namespace.key")` calls had no entry in any locale dictionary, so the
affected screens rendered the raw key on screen (for example
`codegraph.title` instead of `CodeGraph`). This shipped visibly in the
README preview gallery.

### Root cause

The `codegraph`, `toolSuggestions`, and `worktree` namespaces existed only
as `t()` call sites — no locale file was ever created, and none of the
three was registered in `agent-desktop/src/shared/i18n/index.ts`. Seven
more namespaces (`headroom`, `everos`, `tools`, `common`, `welcome`,
`settings`, `sandboxTasks`) had file coverage but were missing the newer
key groups those screens use.

The existing CI gate (`scripts/check-i18n-coverage.cjs`) could not catch
this. Its key regex only matched **quoted** keys, so it parsed 57 keys out
of ~1,470 and compared locales only against each other — never against the
keys the renderer actually calls. It reported `✅ no drift` while six
screens rendered as raw keys.

### What changed

- **New namespaces:** `codegraph.ts`, `toolSuggestions.ts`, and
  `worktree.ts` in `en` (natively written) and `zh-CN` (natively written).
  The other six locales re-export the English file, matching the existing
  `headroom` convention.
- **Extended namespaces:** added the missing key groups to `headroom`,
  `everos`, `tools`, `common`, `welcome`, `settings`, and `sandboxTasks`
  in `en` and `zh-CN`.
- **Registered all three new namespaces** under every one of the eight
  locale `resources` blocks in `src/shared/i18n/index.ts`.
- **`codegraph.repos`** changed from a string to `{ title, empty }` so a
  leaf key can be a namespace prefix; `CodeGraph.tsx` now reads
  `t("codegraph.repos.title")`.
- **Repaired `scripts/check-i18n-coverage.cjs`** to parse bare *and*
  quoted keys and prefix them with the namespace filename. It now sees
  1,573 keys instead of 57.
- **Added `tests/i18n-renderer-keys.test.ts`** — two test cases that fail
  on the previous state: every literal renderer key must resolve to real
  copy in `en`, and must fall back to real copy (not a raw key) in the
  other seven locales.
- **Recaptured `previews/codegraph.png` and `previews/everos.png`**, which
  were the two README images that showed raw keys.
- **Untracked the two committed `__pycache__/*.pyc` files** and ignored
  Python bytecode going forward.

### Follow-up (same release)

Two gaps listed in an earlier draft of this file are now closed:

- **The 14 renderer tests failing on `localStorage` were not "pre-existing
  flakiness" — the jsdom environment had no storage at all.** jsdom returns
  `null` for `localStorage` on an opaque origin, so any component reading it
  threw. Fixed with `environmentOptions.jsdom.url` plus an in-memory `Storage`
  shim in `src/renderer/src/test/setup.ts`. The suite is now fully green.
- **`previews/tools.png` predating the change** — recaptured, along with
  `codegraph.png` and `everos.png`.

## Fifth runtime lane — DeepSeek Harness

The desktop gained a fifth chat runtime, `deepseek-harness`, which it attaches
to by spawning `dsh --profile sdk` and speaking JSON-RPC 2.0 over stdio. There
is no HTTP gateway on that side: every `chat/completions` path upstream is an
*outbound* client, so the catalog entry declares `exposesChatGateway: false`
rather than pretending otherwise.

### Local-first by default

The lane's model route defaults to **Ollama at `127.0.0.1:11434/v1`**. The
runtime's own `dsh-llm-pi-ai` plugin routes to "OpenAI-compatible gateways, or
self-hosted servers", so an Ollama / LM Studio / llama.cpp / vLLM endpoint is
the intended shape, not a workaround. Operator-editable Base URL and Model id
live in Settings with a Test-connection button; a hosted route with an API key
is added through the same fields later. Nothing on the default path needs a
credential or makes an outbound request.

Three defects surfaced by running this against the real runtime rather than a
fixture:

1. pi-ai refuses a route with no credential at all (`PI_AI_ERROR`) before any
   request — local routes carry a fixed placeholder in `apiKeyEnv`.
2. The route's `api:` dictates the wire format; an `openai-completions` route
   fed an Anthropic-shaped stream fails with "Stream ended without
   finish_reason".
3. A `cordis.patch.yml` row for an already-mounted plugin id must be replaced,
   not appended.

### MCP inventory reaches the lane

`mcp_servers:` configured once in the profile now reaches dsh too:
`dsh-mcp-bridge.ts` projects the desktop's inventory into
`$DSH_HOME/cordis.patch.yml` as `@deepseek-ai/dsh-mcp-client` rows. A patch
overlay can only *modify* an existing row by id, so new rows nest under
`- insert:` — a bare top-level row fails composition and the plugin is
silently absent. Verified against `@deepseek-ai/dsh@0.2.2-rc.5`: 34 tools with
one projected server, including `mcp__smoke__smoke_tool`, against 30 without.

The reader moved to `src/main/mcp-config.ts` because `installer.ts` imports
electron and the harness registry is reachable from the console kernel;
`installer.ts` re-exports both names, so no caller changed.
