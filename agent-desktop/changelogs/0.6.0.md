# Changelog — v0.5.0 → v0.6.0

## V2 harvest rollout

A 10-step port of patterns from
[`JZKK720/gstack`](https://github.com/JZKK720/gstack) (workflow
skills) and [`JZKK720/gbrain`](https://github.com/JZKK720/gbrain)
(knowledge brain / synthesis). 8 new main-process modules, 24 new
IPC handlers, 1 new React component, 5 new renderer surfaces, 188
new tests (0 failures, 3 pre-existing skips), 0 regressions.

## Features

### Workflow skills (gstack port)
- **6 gstack skills** under `.agents/skills/` — `careful`,
  `continuous-learning-v2`, `freeze`, `investigate`, `learn`,
  `plan-tune`; each with its own SKILL.md and YAML frontmatter.
  The plans `KNOWN_SKILLS` registry now resolves all six.
- **Bundle test** — `tests/gstack-skills-bundle.test.ts` validates
  frontmatter, source attribution, and cross-references between
  skills.

### /careful destructive-command guard
- **`safety.ts`** — classifies shell commands as
  `safe | warn | block` against 13 destructive patterns with 6
  safe-exceptions (rm-rf of build dirs, git push without --force,
  git reset --soft/--mixed, kubectl delete --dry-run, docker rm
  single, git clean -fd + git checkout).
- **Plans dispatch** runs the plan body through
  `findDestructiveCommandInBody` and returns a
  `DispatchResult.careful` advisory. The Plans screen surfaces it
  as a yellow/red banner.
- **/careful tester** in Settings lets the user verify the matcher
  against arbitrary commands or fenced code blocks.

### /learn durable patterns log
- **`learnings.ts`** — per-profile append-only JSONL log of durable
  patterns / pitfalls / preferences / architecture / tool /
  operational notes. 6 types × 4 sources, key+type dedup with
  count + lastSeen, staleness detection, Markdown export.
- **8 IPC handlers** — read / search / stats / export / findStale /
  clear / fileInfo / append.
- **Learnings tab in Memory** — search + type + source filters,
  add-learning modal, export-as-Markdown copy-to-clipboard, clear.

### /plan-tune decision briefs
- **`<QuestionBrief />` component** — purely presentational
  renderer for `> **D<N> — ...**` briefs: ID, title, ELI10,
  stakes, recommendation, options with pros/cons/effort, Net,
  validation banner. `useQuestionBriefKeyboard` hook for
  Enter-key handling (jsdom-safe).
- **Plans integration** — "Scan for briefs" button per plan,
  per-brief answer inputs, "Apply answers" stitches `## Answers`
  blocks back into the plan markdown.
- **~210 lines of `.plan-tune-brief*` CSS** for light + dark
  mode coverage.

### /brain wiki synthesis layer
- **`schemas.ts`** — 2 bundled schema packs:
  - `cubecloud-base-v1` (6 types: person / project / concept /
    decision / meeting / note)
  - `cubecloud-recommended` (extends base with runbook / learning
    / experiment / faq)
  Profile-scoped active pack persisted as a config value.
  Path-prefix routing for `inferType` (e.g. `people/alice.md` →
  `person`).
- **`synthesis.ts`** — heuristic claim extraction (skips
  headings / fences / blockquotes / table rows / URL lines /
  very short lines), topic scoring with stopwords, dedup by
  text. Returns claims with per-claim citations, sources, gaps,
  freshness, packId, builtAt.
- **`knowledge.ts`** — 4-verb MCP family: `search` / `get` /
  `list` / `sources`, plus an MCP-style tool manifest the
  renderer can register with the agent's tool-use layer.
- **Knowledge + Synthesis panels** in `Memory > Wiki` — 2-pane
  browser with type filter, search box, claim list with
  citations, gaps panel.
- **Schemas section in Settings** — pack picker, infer-type
  demo, type flag indicators (extractable / expert-routing).

### /autoplan dispatch-failure learning
- **`autoplan.ts`** — two halves:
  1. `buildFailureLearning` + `recordDispatchFailure` — appends a
     pitfall learning to `learnings.jsonl` on dispatch failure,
     with a stable dedup key (`stepId + message`).
  2. `extractInlineQuestions` + `buildBriefsForPlan` +
     `applyBriefAnswers` — parses fenced-JSON and blockquote
     `> **D<N> — ...**` forms from plan bodies; returns
     `{stepId, briefs[]}[]` for steps carrying the `plan-tune`
     skill.

## V2.2 addendum — workflow skills + page editing UI

A second pass that landed after the original V2 harvest rolled out.
Two feature batches:

### Workflow skills (`/retro`, `/triage`, `/handoff`)
- **`src/main/retro.ts`** — `/retro` summarises a session into a
  `RetroReport` (highlights, friction, lessons, follow-ups) and
  optionally commits it to learnings. Also exposes `retroBuildContext`
  (for `--continue` flows) and `retroExport` (markdown dump).
- **`src/main/triage.ts`** — `/triage` ranks pending memories +
  learnings by recency × impact, grouped into `act | defer | drop`
  buckets. `triageRecentSessions` seeds the queue from the last
  few sessions for the current profile.
- **`src/main/handoff.ts`** — `/handoff` writes a structured
  `HandoffDoc` (context, open questions, next actions) to
  `~/.hermes/handoff.json` so a follow-up session can pick up
  exactly where the previous one left off.
- **9 new IPC methods** in `src/preload/index.ts` and
  `src/preload/index.d.ts` (`retroSummarize`, `retroBuildContext`,
  `retroCommit`, `retroExport`, `triageItems`, `triageRecentSessions`,
  `handoffBuild`, `handoffSave`, `handoffBuildAndSave`).
- **+57 new tests** (`tests/retro.test.ts`, `tests/triage.test.ts`,
  `tests/handoff.test.ts`).

### Page editing UI (Knowledge Base / raw-sources)
- **`src/renderer/src/screens/Memory/PageEditor.tsx`** — new
  in-page markdown editor for `wiki/*` and `raw/sources/*` pages.
  Modal overlay over the existing read-only viewer, with:
  - Three display modes: **edit**, **split** (default), **preview**.
  - mtime-based conflict detection — the editor re-reads disk
    right before saving and refuses to clobber concurrent writes
    (banner with "reload from disk" / "keep mine, overwrite"
    options).
  - Session-local undo history (capped at 50 steps).
  - Cmd/Ctrl-S to save, Esc to close, Tab inserts 2 spaces.
  - Dirty-check confirm on close.
  - On save: `wikiWritePage` → `wikiAppendLog("edit", ...)` with a
    `layer` tag (`wiki` or `raw`) so audits can separate human edits
    from agent ingests.
- **`src/renderer/src/screens/Memory/Wiki.tsx`** — added an
  **Edit** button in the page-viewer header and mounts
  `<PageEditor>` at the end of the JSX when `editingPage` is set.
  `pageLayer` is derived from `openPage.relPath` (`raw/sources/`
  prefix → `raw`, else `wiki`).
- **CSS**: ~330 new lines in `main.css` (`.wiki-editor-*` and
  `.wiki-page-header-actions` classes) appended after the existing
  wiki block.
- **i18n**: 24 new keys under `memory.wikiEditor.*` in
  `src/shared/i18n/locales/en/memory.ts` (other locales fall back
  to `en` via the existing react-i18next chain).
- **+8 new tests** (`tests/wiki-page-editor.test.tsx`) — load,
  save, mode toggle, conflict path, undo, escape-to-close, raw
  layer, new-page creation.

## Migration notes

- **Existing wiki behavior unchanged.** The Knowledge + Synthesis
  panels are additive — they sit at the bottom of the existing
  `Wiki` tab and don't touch `wikiGetStatus`, `wikiReadIndex`,
  `wikiReadPage`, `wikiAppendLog`, etc.
- **PageEditor is purely additive.** The existing
  `KnowledgePane` / `WikiList` viewers still work exactly as
  before; the new Edit button only appears once a page is open.
  No IPC surface was changed — the editor reuses
  `wikiReadPage` / `wikiWritePage` / `wikiAppendLog` from the
  original V2 wiki module.
- **Plans dispatch still works without the V2 bits.** If the
  plan body contains no destructive commands and no `plan-tune`
  skills, `DispatchResult.careful` is undefined and
  `autoplanBuildBriefs` returns an empty array — the renderer's
  Plans screen gracefully shows no warning panel and no briefs
  panel respectively.
- **No schema-pack migration required.** The default active pack
  is `cubecloud-recommended`. The two bundled packs are
  read-only; no user data is migrated.

## V2.3 addendum — third-party integration (CodeGraph + EverOS)

A third pass that integrates two 3rd-party projects as embedded
runtime modules inside the desktop shell, plus a hidden skills
registry that ships out-of-band of the visible Skills tab.

### CodeGraph runtime (Step 3)
- **`src/main/codegraph-runtime.ts`** — programmatic wrapper around
  the `@colbymchenry/codegraph` library. Per-project LRU cache of
  up to 4 `CodeGraph` instances, lazy `require()` so the SDK is
  only loaded when the CodeGraph screen first opens. The runtime
  exposes `openCodeGraphRuntime`, `closeCodeGraphRuntime`,
  `searchCodeGraphRuntime`, `getImpactRadiusRuntime`,
  `getCodeGraphRuntimeStats`, and `closeAllCodeGraphRuntimes`.
  6 new IPC handlers wire it to the renderer.
- **CodeGraph screen** — the existing `CodeGraph.tsx` now hosts
  an embedded runtime panel: status pill (SDK installed / not
  installed), "open project" button, search box that hits the
  real `searchNodes` API, impact-radius drilldown, live stats.
  Cleanly degrades to an install prompt when the SDK is absent.
- **`@colbymchenry/codegraph` as an optional dep** — installs
  cleanly where the package publishes a wheel; the lazy
  `require()` keeps uninstalled platforms functional.
- **+12 unit tests** in `tests/codegraph-runtime.test.ts` — status
  probes, open/close, LRU eviction, SDK shape drift, graceful
  shutdown via `closeAllCodeGraphRuntimes`.

### EverOS sidecar (Step 4)
- **`src/main/everos-sidecar.ts`** — lifecycle manager for
  `everos server start` as a local child process. Spawns
  `["server", "start", "--host", "127.0.0.1", "--port", "<p>"]`,
  buffers the last 200 lines of stderr/stdout in a ring, monitors
  the child for unexpected exits, and applies a crash-window
  restart policy (1.5s delay, 5 crashes per 60s cap). User-triggered
  restarts clear the crash window so they never burn through the
  budget. Process exits during the `starting` state are not
  counted as crashes.
- **Graceful shutdown** — `before-quit` calls `stopEverOsSidecar`
  which sends SIGTERM with a 3s SIGKILL fallback. Best-effort
  try/catch so a missing binary can't block app exit.
- **EverOS screen** — the existing `EverOS.tsx` now hosts a
  sidecar lifecycle card: state pill (stopped / starting / running
  / crashed), Start/Stop/Restart buttons, log tail in a
  `<details>` panel, clear-logs button. Purely additive over the
  existing `everos:*` HTTP channels.
- **6 new IPC handlers** — `everos-sidecar-status`,
  `everos-sidecar-start`, `everos-sidecar-stop`,
  `everos-sidecar-restart`, `everos-sidecar-log-tail`,
  `everos-sidecar-clear-logs`.
- **+11 unit tests** in `tests/everos-sidecar.test.ts` — state
  transitions, log ring, crash-window counting, graceful shutdown.

### Hidden skills registry + harness dispatcher (Steps 1 + 2)
- **`src/main/skills-harness.ts`** — skills registry resolver that
  consults a hidden manifest path before falling back to the
  visible Skills tab content. Lets us ship workflow skills
  (careful / learn / plan-tune / retro / triage / handoff / etc.)
  out-of-band of the UI without exposing them as new tabs.
- **Chat seam integration** — `src/main/hermes.ts` consults the
  harness on every dispatch. Skills resolved through the harness
  can inject instructions, tool invocations, or memory lookups
  into the agent's reply pipeline.

### Visual + tooling

- **+2 new preview PNGs** — `previews/codegraph.png` (77,984 bytes)

## Migration notes (V2.3)

- **CodeGraph panel is purely additive.** When the
  `@colbymchenry/codegraph` SDK is installed, the CodeGraph screen
  shows the embedded runtime panel; when absent, it shows a clean
  install prompt. The existing `codegraph-cli-status` /
  `codegraph-install-cli` / `codegraph-build-context` /
  `codegraph-export-ua-graph` channels are untouched.
- **EverOS sidecar is purely additive.** The new
  `everos-sidecar-*` channels are independent of the existing
  `everos:*` HTTP channels. Users with a self-hosted EverOS at
  a custom base URL keep using the HTTP channels; users who want
  the desktop to manage a local `everos server start` process
  use the new sidecar card. Both can be configured at the same
  time.
- **Hidden skills registry is silent.** The harness resolves
  skills from a hidden manifest path, but the visible Skills tab
  is unchanged. Users who never had the hidden skills installed
  see no change in the UI; users with the manifest installed
  get the workflow skills injected into the chat seam
  transparently.
- **No new mandatory dependency.** `@colbymchenry/codegraph` is
  declared as an optional dep. Platforms where the package
  doesn't publish a wheel are unaffected — the lazy `require()`
  guards every entry point. The `everos` Python wheel is not a
  declared dep at all; the sidecar resolves the `everos` binary
  via PATH and degrades gracefully if it's missing.
- **Vitest testTimeout raised to 20s** — the previous default of 5s
  was tight enough that `locale-persistence` and `docker-runtimes`
  were hitting it on full-suite runs (both pass in well under 2s
  in isolation). The 20s ceiling gives slow / integration-style
  tests headroom on underpowered CI runners without making
  fast-test feedback any slower.
- **New `npm run smoke` command** — runs `scripts/smoke-all.js`,
  which orchestrates the existing `verify-step3-4-ipc` (12 channels
  from Steps 3+4) + a new `verify-everything` (80 read-only /
  in-staging channels across locale, profile, kanban, plans,
  knowledge, learnings, retro/triage/handoff, careful, discovery,
  files) + a `capture-codegraph-everos` (PNG capture of the two
  new screens). Run it before a release: it exits 1 if any channel
  probe returns a real `TypeError`. Network-bound suites (Nous
  discovery) are skipped by default; opt in with
  `INCLUDE_NETWORK_SUITE=1`.
