# cubecloud-agent-desktop v2.10.84 — release notes

**Source:** `origin/main` of
[JZKK720/cubecloud-agentic-os](https://github.com/JZKK720/cubecloud-agentic-os)
**Supersedes:** v2.10.83 (tag on `origin/main`)
**Commits since v2.10.83:** 21

V2.10.83 → this release is a **correctness release**. Nothing new was added
to the product surface that was not already reachable. What changed is that
several things which reported success now actually work, and several gates
that reported clean now actually check.

The headline: the shipped v2.10.83 installer **could not be verified to
contain** the container runtime fix or A2UI at all — neither is present at
that tag. That is corrected here.

## What this release fixes

### The container runtime path

`isApiServerReady()` — the gate that decides whether a turn goes over HTTP
or falls back to spawning a CLI — built its probe from `getApiUrl()`, which
ignores the environment override. Inside the container that probed the
container's own loopback, found nothing, and fell through to
`sendMessageViaCli`, spawning a binary the image does not ship. Every turn
died with `spawn … ENOENT`.

Fixing `sendMessageViaApi` did not help, because it sits *downstream* of that
gate. The gate now reads the env-aware URL and the env-fallback key.

Verified with no exported variables and only the documented `.env`:

```
POST /api/ag-ui/run   →  200
  TEXT_MESSAGE_CONTENT  delta "RE" / "LEASE" / "_OK"
  RUN_FINISHED
```

37 streamed chunks from a real local model. Not a fixture.

### AG-UI reported empty success on failure

`agUIHarnessSource` turned a harness error into a bare `done`, so a failed
turn produced `RUN_FINISHED{success}` with no text. It now emits an `error`
delta and the run surfaces `RUN_ERROR`. A 180s ceiling produces
`RUN_ERROR{code:"turn-timeout"}` rather than hanging.

The CI smoke was pinning this bug: it accepted an empty `RUN_FINISHED`. It now
requires text content on success, and accepts `RUN_ERROR` only as a failure.

### A2UI had a validator, a renderer, and no producer

`parseA2uiBlock` had zero production callers and `A2uiBlock` was imported by
nothing but its own test. An `a2ui` code fence in an agent message now routes
through `CodeBlock` and renders as a real table.

### Kitesurf and the managed-app roster

Kitesurf is a fully-wired opt-in CDP browser backend, verified against the
real image. Its earlier refusal was withdrawn because the stated reason was
factually wrong. The managed-app roster now renders, so installed adapters are
visible on the Tools screen instead of existing only in the registry.

### 131 lines of mojibake the gate could not see

Nineteen locale files contained UTF-8 bytes that had been decoded as GBK and
re-saved. The result is **valid UTF-8 with zero U+FFFD**, so a
replacement-character scan reported clean for months. Repaired by reversing
the cp936 round-trip; `zh-CN` reached full key coverage. The gate now performs
that round-trip check and flags the class.

### Gates that could not fail

- **`check-skill-counts`** banned every number, which forced `{{SKILLS_TOTAL}}`
  tokens that nothing substituted — the published README rendered the literal
  token in 67 places across 28 files. It now verifies that any number present
  is currently true (48 bundled / 35 upstream / 8 repos, computed from the
  tree), and `scripts/apply-skill-counts.cjs` substitutes from the same truth.
- **`check-doc-pair`** compared English section titles to translated Chinese
  titles, so it could never pass. It now compares H2 counts per document. The
  gaps it had been hiding were real: `SECURITY.zh-CN.md` was 8 sections to
  English's 10, and `THREAT_MODEL.md` 7 to 10 — Chinese was the *more*
  complete file in that pair.
- **The test suite** had `passWithNoTests: true` plus a bare `npm run test`,
  so a moved glob meant green with zero tests. CI now asserts
  `Test Files > 0` and `Tests > 0`.

## Runtime lanes

Raven was documented on port 8855 — a port that never existed. Verified
against the 0.2.8 wheel: `raven serve` defaults to **18792**, and its surface
is `/health`, `/auth` and a WebSocket `/rpc` with 263 methods. There is no
`/v1/chat/completions`, so the desktop auto-detects Raven as a
health-visible fourth lane rather than a chat-completions lane. Its WebUI is
on 18793.

All four lanes were then verified live against their real ports.

IronClaw and OpenClaw are **opt-in**. Their absence is reported as `SKIP`,
not `FAIL`, because a lane nobody started is not a broken lane.

## Developer experience

`npm run dev` could not start at all. electron-vite externalizes
`dependencies`, so the `file:`-linked `@cubecloud/platform-core` produced a
runtime `require()` that resolved nowhere:
`ERR_MODULE_NOT_FOUND`. Fixed with
`build.externalizeDeps: { exclude: [...] }`. A dev-mode boot check now runs in
CI, because no unit test could see a bundler config error.

Two test-suite reliability fixes: `maxWorkers: 4` (the 32-core default
over-subscribed; different tests timed out on different runs at the same
commit), and the `ssh-remote` timeout raised from 20s to 60s, derived from
measurement — `bash -lc` costs ~3952ms on Windows for WSL cold start, and the
file's own 20s bump equalled the global cap so it did nothing.

One genuine race fixed: the `headroom-learn` apply `describe` never reset the
shared module-level `spawnMock`, so "has spawn been called?" was true before
the current call existed. The child's `close` was emitted before the listener
attached, the `await` never settled, and vitest reported a 20s timeout instead
of an assertion failure.

## Known remaining gaps

- **Six locales are ~340 keys short of English** and fall back to English copy
  by design. `check-i18n-coverage` reports this and gates it informational,
  with `--strict` available. This is translation work, not a defect.
- **IronClaw chat is blocked by host VRAM** (4GB AMD Radeon 8060S iGPU), not
  by code.
- **univer** awaits a licence decision before any read-only viewer work.
- **astryx** stays unadopted: it is a design system, not a service, and its
  70 custom properties do not fit the current surface.
- Each of these verdicts rests on reading the repos and the code. Only a real
  operator install converts them into requirements.
