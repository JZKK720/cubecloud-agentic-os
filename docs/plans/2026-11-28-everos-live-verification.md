# 2026-11-28 — Live EverOS v2 verification (Ollama backend)

> **Result: the EverOS v2 path works end to end against a real local server.**
> This closes the "search never verified against a live server" gap from the
> previous report. All evidence below is from one run on this machine.

## What was configured

Server started as a scratch instance, not the developer default root:

```
python -m everos.entrypoints.cli.main server start --root "$env:TEMP\everos-live-root" --port 8012
```

`everos.toml` (generated by `everos init`, then edited) points the default LLM at a locally served model and the embedding at Ollama:

| Section | Value | Why |
|---|---|---|
| `llm.model` | `ornith-1.5:9b` | small local model already present via `ollama list` |
| `llm.base_url` | `http://127.0.0.1:11434/v1` | Ollama OpenAI-compatible endpoint |
| `llm.response_format_mode` | `json_object` | Ollama rejects `json_schema`; default is `json_schema` |
| `llm.api_key` | `ollama-local` | required non-empty by the client; not a real credential |
| `embedding.model` | `nomic-embed-text:latest` | local, 768-dim |
| `embedding.base_url` | `http://127.0.0.1:11434/v1` | same endpoint |
| `embedding.dim` | `768` | **must match the model output dim or startup refuses** |
| `rerank.model` / `rerank.base_url` | `""` | disabled; otherwise server treats it as configured and fails at search time |
| `rerank.provider` | `deepinfra` (unchanged) | irrelevant once model/base_url are empty |

Health after configuration: `200 {"status":"ok","version":"1.8.0","capabilities":{"embed":true,"rerank":false,...},"disabled_features":["agentic_search","knowledge"]}`.

## What was exercised (live, over HTTP)

`POST /api/v2/memory/add` with two messages in a unique session → `200 {"status":"accumulated"}`.
`POST /api/v2/memory/flush` → `200 {"status":"extracted"}` — the local LLM actually extracted an episode.

`POST /api/v2/memory/get` → `200`, one episode with `id` `agent-desktop-smoke_ep_...`, `app_id: agentic-os`, `project_id: agentic-os-smoke`, summary text naming the marker passphrase `AURORA-7742`.

`POST /api/v2/memory/search` against `AURORA-7742`, all three methods:

| Method | Status | Top hit | Score |
|---|---|---|---|
| `hybrid` | 200 | AURORA-7742 episode | 0.490 |
| `keyword` | 200 | AURORA-7742 episode | 0.904 |
| `vector` | 200 | AURORA-7742 episode | 0.754 |

All three return `app_id: "agentic-os"`, same session, same episode id. Scope isolation held on every call.

Desktop-side smoke: `EVEROS_SMOKE_URL=http://127.0.0.1:8012 npx vitest run tests/everos-v2.smoke.test.ts` → **2 passed** (previously the search assertion could only degrade to "expected EXTERNAL_SERVICE_UNAVAILABLE"; with a real embedding backend it now exercises the real search path).

## Honest limits

- Port 8012 was a throwaway server on this machine; it was stopped after the run and the root lives in `%TEMP%`.
- The smoke test still contains a fallback that accepts `EXTERNAL_SERVICE_UNAVAILABLE` on machines with no embedding backend — that is intentional for CI, but it means a green smoke test does not by itself prove retrieval works. This document is the evidence that it does.
- No multimodal, agent_case, agent_skill, knowledge-topic or cascade paths were exercised.
- `nomic-embed-text` is 768-dim; a production deployment must set `embedding.dim` to match whatever model it actually runs, or retrieval silently degrades.
- Ollama `chat/completions` accepts `json_schema` in the request but honours it only because `json_object` was forced here; do not assume `json_schema` semantics on Ollama.
